# 02 — Core Pillars

Every system, quest, and feature in Project Elysium should be measurable against these six pillars. If a proposed feature doesn't clearly support at least one, it should be reconsidered.

## 1. Exploration is Always Rewarding
No region is filler. Every zone hides at least one landmark, secret, or piece of lore (see [015-Landmarks.md](015-Landmarks.md)) that isn't required by any quest — pure discovery content for players who wander off the path.

## 2. Every Area Has Purpose
Zones are scoped to a level range, a faction presence, and a narrative beat before a single block is placed. See [012-Regions.md](012-Regions.md) for how regions are planned against the leveling curve in [046-Leveling.md](046-Leveling.md).

## 3. Progression is Meaningful
Talent choices, gear upgrades, and profession milestones (see [043-Talent-Trees.md](043-Talent-Trees.md), [060-Professions.md](060-Professions.md)) should change how a player plays, not just their numbers on a tooltip.

## 4. Multiplayer Encourages Cooperation
Systems favor group play without punishing solo players — dungeon finder queues, guild perks, and world events (see [083-Dungeon-Finder.md](083-Dungeon-Finder.md), [019-World-Events.md](019-World-Events.md)) are built to make grouping the natural, rewarding choice.

## 5. Quality Over Quantity
A smaller, polished continent beats a larger, empty one. Content is not shipped until it meets the bar set in [140-Development-Standards.md](140-Development-Standards.md).

## 6. Documentation is Part of Development
No system is considered "done" until it is documented here. Undocumented features are treated as unfinished features — see [140-Development-Standards.md](140-Development-Standards.md) for the documentation-first workflow.
