## 1. Overview

This document consolidates the recurring operational checklists referenced throughout this folder into a single practical reference, supporting the weekly operating rhythm described in [2000-Live-Service.md](2000-Live-Service.md).

## 2. Daily Checklist

* Review server health dashboards ([1216-Monitoring.md](../1200-Technical/1216-Monitoring.md)).
* Review overnight support ticket queue ([2005-Support-System.md](2005-Support-System.md)) and moderation report queue ([2003-Moderation.md](2003-Moderation.md)).
* Scan community channels for emerging sentiment or issues ([2013-Player-Feedback.md](2013-Player-Feedback.md)).

## 3. Weekly Checklist

* Cross-team sync reviewing open issues, upcoming content, and metrics ([2015-Game-Metrics.md](2015-Game-Metrics.md)).
* Weekly restart execution and communication ([2011-Server-Restarts.md](2011-Server-Restarts.md)).
* Review bug report backlog ([2014-Bug-Reports.md](2014-Bug-Reports.md), [1407-Bug-Tracking.md](../1400-Development/1407-Bug-Tracking.md)).

## 4. Per-Release Checklist

* Complete QA sign-off per [1406-Testing.md](../1400-Development/1406-Testing.md).
* Draft and review patch notes ([2002-Patch-Notes.md](2002-Patch-Notes.md)).
* Schedule and communicate the release window ([2001-Updates.md](2001-Updates.md), [2004-Community-Management.md](2004-Community-Management.md)).
* Post-release monitoring window per [1408-Release-Process.md](../1400-Development/1408-Release-Process.md).

## 5. Incident Response Checklist

* Confirm and assess severity.
* Communicate initial acknowledgment through appropriate channels ([2004-Community-Management.md](2004-Community-Management.md)).
* Coordinate technical response ([1206-Security.md](../1200-Technical/1206-Security.md), [1230-Server-Maintenance.md](../1200-Technical/1230-Server-Maintenance.md) as relevant).
* Post-incident review and, where appropriate, player compensation per [2011-Server-Restarts.md](2011-Server-Restarts.md).

## 6. Ownership and Maintenance

This checklist is maintained by the live operations lead and reviewed after any incident or major release reveals a gap, ensuring it reflects genuinely current practice rather than becoming stale documentation.
